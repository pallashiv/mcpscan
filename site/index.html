Static security scanner for MCP servers

A linter for MCP servers,
not a leap of faith.

MCP servers tell your AI assistant what tools it can use — in plain text the assistant trusts. mcpscan reads that text and catches what shouldn't be there: hidden instructions, hardcoded secrets, and servers that quietly rewrite a tool after you've already approved it.

Every report above runs entirely in your browser. Each one carries a Content-Security-Policy that allows only its own code and blocks all network access — so even the deliberately hostile example can't send anything anywhere. mcpscan itself works the same way: it reads one file you point it at and never connects to anything, which is the whole reason a security tool is safe to point at a company's servers.

What it actually checks

17 rules across two inputs: the tools a server declares, and the config that launches it.

Tool poisoning & prompt injection

Hidden instructions, invisible Unicode, and forced tool calls in a tool's own metadata.

Hardcoded secrets & weak schemas

API keys in a config, plaintext HTTP, and command-like parameters with no constraints.

Rug-pull detection

A lock file fingerprints every tool at approval time, so a later rewrite gets caught, not missed.

CI-ready output

SARIF for GitHub code scanning, baseline/ignore files so adoption doesn't fail the build, and a GitHub Action.

Try it yourself

Zero dependencies, Python 3.9+. It reads a file and prints a report — nothing more.

# scan a tool manifest or a Claude Desktop / mcp.json config
pip install git+https://github.com/pallashiv/mcpscan.git
mcpscan scan tools.json --format html --output report.html
